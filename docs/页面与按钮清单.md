# 页面与按钮清单（权限口径 · 唯一对照表）

> 本表是全站「页面 → 按钮 → 权限点」的唯一对照表，与 `src/data/perm.js` 一一对应。
> 改页面按钮时，**先改本表，再改 perm.js，最后确认按钮挂了 `v-can`**；三处不一致就会出现
> 「权限管理里能勾、页面上没这个按钮」或「页面上有按钮、却没有对应权限」。
>
> 统计：**7 个模块 / 22 个页面 / 88 项权限点**。
> 界面上的所有计数都由 `TOTAL_PERMS` 推导，不要在任何页面写死数字。

## 一、口径

1. 每个页面第一项固定是「查看页面」：由路由守卫 + 侧边栏菜单使用，勾了才能进页面，
   只勾它则该职位「能看不能动」。
2. 带 **（只读）** 的项（查看详情 / 查看盘点单 / 查看库存调整单 / 查看职位详情）随
   「查看页面」自动授予，登录侧 `withReadItems()` 与权限树 `onCheck()` 两侧口径一致；
   它们**不能单独取消**，想收回只能整页取消「查看页面」。
3. 会改数据或改变可见范围的动作才占一个权限点；每个受控按钮都必须挂 `v-can`，
   没挂的按钮等于对所有能进这页的人开放。
4. id 约定 `b-<页面短名>-<动作>`，页面节点 `p-<页面短名>`，模块节点 `m-<模块>`。
5. **不单独授权**：查询 / 查找 / 搜索 / 重置 / 刷新 / 取消 / 返回 / 关闭 / 页签切换 /
   权限树「全选 / 清空 / 展开」（未点保存前）都属于浏览行为，由「查看页面」覆盖。
   弹窗内的「确定 / 提交」跟随打开它的那个按钮，不重复占权限点。

## 四、本轮清理掉的「不对 / 多余」内容

| 类别 | 旧内容 | 处理 |
|---|---|---|
| 按钮改名 | 订单审核「编辑」 | 改为「查看详情」（只读项），另三个订单页、售后三页同样统一为「详情」 |
| 已不存在的权限点 | 编辑职位、查询对账 / 查询发货数据 / 查询应付台账、导出采购单 | 从树中删除，由「查看页面」或对应动作覆盖 |
| `system.js` 里的第二份旧权限树 | 75 项，含「编辑订单」「打印面单」「撤回订单」「复制信息」「历史采购单」「仓库盘点」等页面上没有的按钮 | 整份删除；职位默认权限改由 `perm.js` 统一发放，避免两份清单走岔 |
| 名称与界面不符 | 「编辑仓库」 | 改为「更改负责地区」（对应行按钮「更改」） |
| 名称覆盖不全 | 「维护供货货品」 | 改为「维护供货货品（新增 / 移除）」，并把货品行「移除」挂上权限 |
| 缺少的只读项 | 库存调整单、职位详情 | 补「查看库存调整单」「查看职位详情」 |
| 未受控的按钮 | 供应商货品「移除」、职位人员「移除」、库存调整单入口、审核弹窗「驳回」、批量栏「全部驳回」 | 补挂 `v-can`，与权限点一一对应 |
| id 命名 | `b-order-export` / `-export2` / `-export3` / `-export4` | 统一为 `b-order-<页面>-export`；`LEGACY_ID` 自动迁移本地已保存的分配结果，升级后导出权限不会丢 |

## 五、维护检查单

- [ ] 新按钮：加 `v-can` → 在 `perm.js` 对应页面加权限点 → 更新本表 → 构建 + 看权限树计数。
- [ ] 删按钮：删 `v-can` → 删权限点 → 更新本表 → 确认没有职位默认权限还引用旧 id。
- [ ] 只改名：改 `perm.js` 的 label 和本表，id 保持不变（改 id 必须同时写 `LEGACY_ID` 迁移）。
- [ ] 权限树里不允许出现页面上不存在的按钮；页面上有 `v-can` 的按钮必须能在树里找到。
