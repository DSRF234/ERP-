# 开发规范

## 一、为什么要有这份规范

三个人各写各的，最后拼起来一定像三个产品。这份规范的目的是：**任何一个人写的页面，另一个人接手时不需要重新学一遍。**

## 二、页面结构唯一模板

所有列表页都是「标题区 → 筛选区 → 表格区」三段，不允许发明第四种布局。

```vue
<PageHeader title="..." sub="..."> 操作按钮 </PageHeader>
<div class="filters"> 筛选控件 </div>
<div class="card"> 表格 </div>
```

筛选区统一用 `el-select` / `el-radio-group` / `el-input`，`size="small"`，间距 10px。

## 三、状态与标签

| 语义 | 组件 | 颜色 |
|---|---|---|
| 已完成 / 正常 | `el-tag type="success"` | 绿 |
| 进行中 / 部分完成 | `el-tag type="warning"` | 橙 |
| 异常 / 失败 | `el-tag type="danger"` | 红 |
| 未开始 / 中性 | `el-tag type="info"` | 灰 |

不要用自定义背景色做标签，色值会不统一。

## 四、表单

- 统一 `label-width="96px"`
- 必填项加 `rules`，不要只画红星
- 提交前必须做前端校验，后端校验不替代前端
- 错误提示用 `ElMessage.error`，不要 `alert`

## 五、空状态与加载

- 表格无数据：`<el-empty description="暂无数据" />`（el-table 自带空状态，可自定义）
- 加载：`v-loading="loading"`
- 请求失败：`ElMessage.error(msg)`，不要静默失败

## 六、金额与日期

```js
// 金额：千分位 + 两位小数，空值显示 —
const money = v => (v == null ? '—' : v.toLocaleString('zh-CN', {
  minimumFractionDigits: 2, maximumFractionDigits: 2
}))

// 日期：YYYY-MM-DD
const date = d => dayjs(d).format('YYYY-MM-DD')
```

**禁止在模板里直接写 `toFixed`**，四舍五入规则要统一。

## 七、禁止事项

- ❌ 引入新的 UI 库（Ant Design、Vant 等）
- ❌ 引入 CSS 框架（Tailwind、Bootstrap）
- ❌ 在组件里写全局 `<style>`（必须 `scoped`）
- ❌ 直接操作 DOM（用 `ref` 和 Vue 的方式）
- ❌ 把业务逻辑写进 `api/`（api 只负责取数）
- ❌ 提交 `node_modules`、`dist`、`.env.local`
