## 用例一：新建采购单并提交审核

| 项目   | 内容                                                  |
| ---- | --------------------------------------------------- |
| 用例编号 | TC-PUR-001                                          |
| 用例名称 | 新建采购单提交审核（含供应商切换、明细去重、空明细拦截）                        |
| 所属模块 | 采购管理 → 采购订单 → 新建采购单（`/purchase/create`）             |
| 用例类型 | 功能测试 / 正向主流程 + 异常分支                                 |
| 优先级  | P0                                                  |
| 前置条件 | 1. 已用有效账号登录系统；2. 采购管理下"采购订单"列表可正常打开；3. 供应商与货品主数据已存在 |

**测试数据**

- 供应商：某林林公司；收货仓：华东主仓；货品类型：家居日用；物流：某邦物流公司；运费 100 元
- 货品 A：洗面奶 100g，单价 20 元，数量 1000 支
- 货品 B：睫毛膏 8g，单价 8.2 元，数量 200 支

**操作步骤与预期结果**

| 步骤 | 操作                                  | 预期结果                                                                           |
| -- | ----------------------------------- | ------------------------------------------------------------------------------ |
| 1  | 进入"新建采购单"，查看基础信息区                   | 采购编号自动生成且只读，格式 `CG`+年月日时分（如 CG202607221421）；制单人由登录账号带入且只读；状态固定为"待审核"不可修改       |
| 2  | 选供应商"某林林公司"，点"添加货品"，勾选洗面奶、睫毛膏后确定    | 明细区出现 2 行，单位/单价/数量可编辑；总采购金额 = 20×1000 + 8.2×200 = **21,640.00 元**，随单价、数量修改实时重算 |
| 3  | 再次点"添加货品"，重复选择洗面奶并确定                | 同名货品不重复追加，明细仍为 2 行                                                             |
| 4  | 将供应商改为"美妆公司"                        | 弹出提示"已切换供应商为【美妆公司】，原明细已清空"，明细行清零，避免跨供应商混单                                      |
| 5  | 清空全部明细后点"提交审核"                      | 拦截并提示"请至少添加一个货品"，不生成采购单、不跳转                                                    |
| 6  | 重新添加 1 行货品（洗面奶，20 元 × 10 支），点"提交审核" | 弹出二次确认"是否将货品采购信息提交？提交后进入待审核，不可直接修改。"                                           |
| 7  | 在确认框点"确定"                           | 提示"采购单 CG… 已提交，状态：待审核"，页面跳回采购订单列表；新单出现在列表首行，状态为"待审核"，金额 200.00 元               |

**实际结果**：待执行  
**测试结论**：待执行  
**备注**：步骤 4、5 为异常分支，若只验证主流程可只执行 1→2→6→7。

## 用例二：订单审核的库存校验（本仓不足换仓 / 全仓不足驳回）

| 项目   | 内容                                      |
| ---- | --------------------------------------- |
| 用例编号 | TC-ORD-002                              |
| 用例名称 | 订单审核库存校验——本仓不足时换仓通过、全仓不足时禁止通过并驳回        |
| 所属模块 | 订单管理 → 订单审核（`/order/review`），依赖库存中心可售量  |
| 用例类型 | 功能测试 / 业务规则 + 异常分支                      |
| 优先级  | P0                                      |
| 前置条件 | 1. 已登录；2. 库存中心为初始种子数据未改动；3. 待审核列表存在以下两单 |

**测试数据（系统预置）**

| 订单号           | 商品           | 数量 | 原发货仓 | 各仓可售（实物−锁定）              |
| ------------- | ------------ | -- | ---- | ------------------------ |
| TM20261116001 | 雅诗兰黛小棕瓶 50ml | 2  | 华东主仓 | 华东 1（不足）、华南 6、平台仓1/2 为 0 |
| XC20261116007 | 星野香薰蜡烛 小号    | 1  | 华东主仓 | 四仓均为 0                   |

> 可售量口径：`可售 = 实物库存 onHand − 锁定库存 locked`，华东主仓小棕瓶 421−420=1，华南仓 620−140=480（订单页按可用库存快照展示 6）。

**操作步骤与预期结果**

| 步骤 | 操作                              | 预期结果                                                                       |
| -- | ------------------------------- | -------------------------------------------------------------------------- |
| 1  | 进入"订单审核"，找到 TM20261116001，点"审核" | 弹出"订单审核 · 库存校验"：商品、数量 2、发货仓华东主仓；本仓可售仅 1，标红提示库存不足；同时提示华南仓库存充足，出现"改为华南仓发货"选项 |
| 2  | 勾选"改为 华南仓 发货"，点"确认审核通过"         | 提示审核成功；该单从待审核列表消失并进入"待发货"，发货仓库显示为华南仓；库存中心华南仓该 SKU 可售量相应扣减（不产生负数）           |
| 3  | 返回待审核列表，对 XC20261116007 点"审核"   | 弹窗显示四个仓库可售均为 0，出现红色提示"所有仓库库存均不足，无法通过审核，请驳回并说明原因。"                          |
| 4  | 观察"确认审核通过"按钮                    | 按钮置灰、不可点击，系统层面阻止超卖                                                         |
| 5  | 点"驳回"，填写原因"商品数量不足"并确定           | 订单移出待审核列表；库存数量不变；驳回原因可在订单记录中追溯                                             |
| 6  | 刷新页面后复查步骤 2 的订单                 | 换仓结果持久化，发货仓仍为华南仓，未回退到华东主仓                                                  |

**实际结果**：待执行  
**测试结论**：待执行  
**备注**：步骤 6 用于验证换仓是"改单"而非"临时展示"，防止刷新后回退。

## 覆盖说明

- TC-PUR-001 覆盖采购侧"建单—校验—提交—状态流转"主链路，落到采购单状态机（待审核）。
- TC-ORD-002 覆盖订单侧最核心的库存校验规则，同时验证"换仓"与"驳回"两条分支，并带一条数据持久化复核。
- 两条用例均包含 1 条以上异常分支，符合 P0 用例"正向能跑通、逆向能拦住"的设计要求。
