### 1.1 术语与口径（阅读用例前必读）

| 术语 | 含义 | 易混淆点 |
| --- | --- | --- |
| 申请售后类型（`applyType`） | **客户提交售后时选的原由**：退货退款 / 仅退款 / 部分仅退款 / 换货 / 补发 / 补差价 / 更改地址 | 列表「申请售后类型」列显示的就是它，审核后不再变化 |
| 处理方式（`type`） | **客服审核时最终认定的处理方式**：退货 / 仅退款 / 部分仅退款 / 换货 / 补发 / 补差价 / 更改地址 | 审核弹窗里可以改；审核后列表「处理方式」列显示它 |
| 仅退款类 | 仅退款、部分仅退款、补差价三类，**同意即原路打款并直接进入「处理完成」**，不进「处理中」 | 退货即使「无需寄回」也要先进入处理中·待退款 |
| 寄回类 | 退货（要求寄回）、换货、补发，同意后进入处理中对应队列 | 换货/补发不经过「待客户退回」 |
| 队列（`queue`） | 处理中的 7 个环节：待客户退回 `back`、退回在途 `transit`、已收货待质检 `qc`、待退款 `refund`、换货待发货 `exchange`、待补发 `resend`、地址变更待生效 `address` | 队列数之和必须等于「全部处理中」 |
| 权限点 | 权限树最小单元：每个页面第一项固定是「查看页面」，其余为页面内按钮 | 全站 7 模块 / 22 页面 / **84 项权限点**（勿与旧文档的 71/75/80 混淆） |
| 数据范围 | 职位属性：全部数据 / 本部门及下级 / 本部门 / 仅本人 / 自定义 | **本系统仅作为字段展示与保存**，不参与列表过滤 |

> 关键代码：`data/system.js`（职位 / 账号 / 仓库 / 启停规则）、`data/perm.js`（权限树 / 默认权限 / 持久化）、`stores/user.js`（登录与账号桥接）。
