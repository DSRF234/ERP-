### 2.3 权限口径

- 结构：**7 个模块 → 22 个页面 → 84 项权限点**（每个页面第一项固定为「查看页面」，其余为实际按钮）。
- 四条硬规则：
  1. 勾任一操作 → 自动补上该页「查看页面」；
  2. 取消「查看页面」→ 该页所有操作一并清空；
  3. 勾模块 → 其下全部页面与操作一并勾选，取消任一子项模块变半选；
  4. 未勾选的页面 → 菜单不出现、地址栏直连被路由守卫拦截。
- 售后相关权限点：待处理 3 项（查看 / 审核售后单 / 导出售后单）、处理中 5 项（查看 / 确认退款 / 创建换货单 / 创建补发单 / 完成改址）、完成 3 项（查看 / 导出售后单 / 复制单据信息）。
- 系统相关权限点：职位管理 7 项、账号管理 6 项、权限管理 3 项、发货仓设置 3 项。

## 六、缺陷与观察项

### 6.1 已修复缺陷（本轮测试发现并修复）

| 编号 | 缺陷 | 位置 | 现象 | 修复 |
| --- | --- | --- | --- | --- |
| BUG-01 | 权限树「取消查看页面 → 清空该页操作」失效 | `views/system/permission.vue` `onCheck()` | 取消某页「查看页面」后操作仍在、已勾数不变：补齐规则把刚取消的查看权又加了回去 | 改为按被点击节点分流：用户主动取消的是「查看页面」时先清空该页操作且不再补回；其余情况执行补齐 + 兜底清理 |
| BUG-02 | 账号管理与登录是两套账号数据 | `views/system/account.vue`、`stores/user.js`、`data/system.js` | 新建账号列表可见却登录提示「账号不存在」；停用 / 删除 / 改职位不影响登录；老板账号台账 `qitian` 与登录 `admin` 不一致 | 新增 `accountBridge`（add / update / setStatus / remove），账号页的新增、改名、改职位、停用、删除、重置密码同步到登录侧；`login()` 增加停用校验；老板账号统一为 `qitian` |

### 6.2 待修复缺陷（本轮新发现，尚未改动代码）

| 编号 | 缺陷 | 位置 | 复现步骤 | 影响与建议 |
| --- | --- | --- | --- | --- |
| BUG-03 | 重置密码对「改过密码」的账号无效，且不会让会话失效 | `views/system/account.vue` `resetPwd()` → `accountBridge.update(row.account, { password: INIT_PASSWORD })`；`stores/user.js` `login()` 中改密记录优先于账号初始密码 | ① 用 `wangjl` / `Xy@2026` 登录 → 顶栏「修改密码」改为 `NewPass123` → 退出；② 管理员在账号管理点该账号「重置密码」→ 提示已重置为 `Xy@2026`；③ 用 `NewPass123` 登录 → **仍然登录成功** | 改密记录存在 `localStorage.xy_erp_pwd_map` 且优先级高于账号初始密码，重置只改了后者；同时确认框承诺「当前登录状态立即失效」并未实现。建议新增 `accountBridge.resetPassword(account)`：写入 `Xy@2026` 的同时删除 `pwdMap` 中该账号条目；若要求「立即失效」，需清理 `xy_erp_user` 或引入会话版本号 |

| 编号 | 观察项 | 位置 | 说明 |

## 七、已知限制（非缺陷）

1. **业务数据为前端内存态**：账号、职位、售后单据、发货仓均存于内存，刷新即回种子状态。仅权限分配（`xy_erp_post_perms`）与登录态（`xy_erp_user`）、改密记录（`xy_erp_pwd_map`）写入 localStorage。属演示数据层设计，接后端后自然消失。
2. **新建职位 / 账号不落盘**：同上，刷新后消失，不影响单次演示流程。
3. **质检结论不可在 ERP 内录入**：质检由 WMS 执行并回传，ERP 只展示「已收货待质检」并锁定动作，因此「质检 → 待退款」的自动流转无法在纯前端验证。
4. **审核弹窗的「部分同意」对退货类等价于调整金额**：判定表见附录 B，与「部分仅退款」的区别只体现在处理方式字段上。
